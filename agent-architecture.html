核心逻辑：主 Agent 澄清意图，子 Agent 澄清参数

这张图只保留当前 demo 最关键的流转：用户提出教学需求后，主 Agent 先确认“要解决什么问题”和任务关系，然后输出可解释的执行规划；进入执行阶段后，每个子 Agent 再补齐自己需要的班级、时间、难度、格式等参数，最后开始工具调用和产物生成。

对应 agent-demo.html 的真实流程
01
💬用户需求
老师输入一句话，也可能带图片、Excel、知识库文件。
step3_userMsg
02
🧠主 Agent 识别意图
判断是单任务还是多任务，任务之间是否有依赖。

❔主 Agent 意图澄清
只确认目标和任务关系，例如“先分析再生成课件”还是“只要报告”。

📋主 Agent 输出规划

📄汇总与展示

step7_reply

有依赖：串行执行

例如“先分析学情，再生成讲评课件”。课件生成 Agent 必须等待学情分析 Agent 输出“3 个共性问题”，再把这个结果作为输入继续执行。

无依赖：并行执行

例如“同时生成数学卷和语文阅读练习”。两个子 Agent 不共享前序结果，可以同时运行，前端用并行任务列展示进度。

前端只需要把 4 类信息展示清楚

1. 主 Agent 意图澄清
告诉老师现在只确认“目标是什么”，不急着问参数。
2. 主 Agent 执行规划
解释为什么串行、为什么并行，以及会调度哪些子 Agent。
3. 子 Agent 参数澄清
每个执行 Agent 问自己需要的班级、时间、难度等参数。
4. 子 Agent 工作过程
展示读取数据、扫描作业、生成课件等工具调用过程。
一句话总结：主 Agent 负责“我要做什么、怎么安排”；子 Agent 负责“我执行前还缺哪些参数、具体怎么做”。demo 现在会先出现主 Agent 意图澄清，再出现主 Agent 规划，随后才由子 Agent 参数澄清并开始工作。
